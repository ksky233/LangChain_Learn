# 事件循环与协程：从 `await` 到 `create_task` / `gather`

这篇笔记整理的是 Python `asyncio` 的核心心智模型，重点回答几个学习异步 API 时最容易卡住的问题：

- `await` 到底是在“等待”还是在“暂停”？
- `create_task()` 创建任务后，任务什么时候真正开始运行？
- 直接 `await`、`create_task()`、`asyncio.gather()` 有什么区别？
- 为什么异步并发不是 CPU 层面的真正并行？
- 为什么异步代码里不能随便写 `time.sleep()`？

这些概念对理解 LangChain 的 `ainvoke()`、`astream()`、`abatch()` 很重要。LangChain 的异步 API 本质上也是运行在 Python 的事件循环机制之上。

## 1. 总体关系

先把层级关系放清楚：

```text
操作系统
  └─ Python 进程：python.exe
      ├─ 主线程
      │   └─ 事件循环 event loop
      │       ├─ Task 1：main()
      │       ├─ Task 2：model.ainvoke(...)
      │       ├─ Task 3：asyncio.sleep(...)
      │       └─ ...
      └─ 其他线程：如果程序或库额外创建了线程，才会有
```

进程和线程是操作系统层面的概念；事件循环和协程是 Python 运行时层面的调度机制。

通常执行一个脚本：

```powershell
python ainvoke_2.py
```

操作系统会启动一个 Python 进程，也就是任务管理器里看到的 `python.exe`。这个进程里至少有一个主线程。`asyncio.run(main())` 会在这个主线程里创建事件循环，然后把 `main()` 这个协程交给事件循环调度。

`main()` 不是线程。`async def main()` 定义的是一个协程函数，调用 `main()` 得到的是一个协程对象。协程需要被事件循环调度后才会真正运行。

## 2. 几个核心概念

### 协程函数

用 `async def` 定义的函数：

```python
async def main():
    ...
```

它不是普通函数。调用它时不会立刻执行函数体，而是返回一个协程对象。

```python
coro = main()
```

### 协程对象

协程对象表示“一段可以被暂停和恢复的异步计算”。它本身还不是后台任务。

### Task

Task 是事件循环真正调度的任务单位。

```python
task = asyncio.create_task(model.ainvoke("你好"))
```

`create_task()` 会把一个协程对象包装成 Task，并登记到事件循环里。之后事件循环有机会时，就会推进这个 Task。

### 事件循环

事件循环可以理解成一个调度器。它不断做类似这样的事情：

```text
找一个可以运行的任务
运行它
如果它遇到 await 并且要等待 I/O，就暂停它
再去运行下一个可以运行的任务
某个 I/O 完成后，把对应任务重新放回可运行队列
```

你一般不直接控制事件循环怎么切换任务，而是通过 `await`、`create_task()`、`gather()` 等 API 把任务交给它。

## 3. `await` 的真实含义

`await` 从代码表面看是“等待”，但从运行机制看更准确是：

```text
暂停当前协程，把控制权交还给事件循环；
等右侧 awaitable 完成后，再从这里恢复当前协程。
```

比如：

```python
response = await model.ainvoke("你好")
print(response.content)
```

对当前协程来说，它确实是在等待模型返回。`print()` 不会提前执行。

但它不是把整个线程堵住。当前协程在等待模型网络响应时，会把事件循环让出去。事件循环可以趁这个时间去运行别的任务。

所以 `await` 有两层含义：

- 对当前协程：暂停，等右侧任务完成。
- 对事件循环：让出控制权，让其他已调度任务有机会运行。

一句话记忆：

```text
await 不是开新线程。
await 是“我现在要等东西，先暂停我，事件循环你去调度别人”。
```

## 4. 直接 `await`：顺序等待

直接 `await` 是最简单、最清楚的异步写法：

```python
response = await model.ainvoke(question)
history = await load_history(user_id)
profile = await load_profile(user_id)
```

这段代码是顺序执行：

```text
先等模型完成
再等 history 完成
再等 profile 完成
```

每一行 `await` 都会暂停当前协程，但下一行不会提前执行。也就是说，直接 `await` 并不会自动让这三个任务并发。

直接 `await` 大致可以理解成：

```python
coro = load_history(user_id)
history = await coro
```

它会创建协程对象并等待它完成，但这个协程没有被注册成独立后台 Task。它更像是当前 Task 的一段嵌套异步调用。

所以：

```python
history = await load_history(user_id)
profile = await load_profile(user_id)
```

含义是：

```text
main 暂停，等待 load_history 完成
load_history 完成后，main 恢复
main 再开始 load_profile
main 暂停，等待 load_profile 完成
```

这适合当前流程里只有一个异步动作，或者几个动作本来就存在依赖关系的场景。

## 5. `create_task()`：先启动，稍后再拿结果

如果你希望某个协程先作为后台任务开始运行，同时当前协程继续往下走，可以用 `create_task()`：

```python
model_task = asyncio.create_task(model.ainvoke(question))

history = await load_history(user_id)
profile = await load_profile(user_id)

response = await model_task
```

这段代码的语义是：

```text
1. 先把模型调用注册成后台 Task。
2. 当前 main 协程继续执行。
3. main 在 await load_history(...) 时暂停，把事件循环让出去。
4. 事件循环现在可以推进 model_task，也可以推进 load_history。
5. 在等待 history/profile 的过程中，模型请求可能已经开始，甚至可能已经完成。
6. 最后执行 response = await model_task。
   如果模型任务已经完成，直接拿结果；
   如果还没完成，就继续等待。
```

这类写法常见于真实业务流程：

```python
model_task = asyncio.create_task(model.ainvoke(question))

# 趁模型等待网络返回，继续准备其他数据
history = await load_history(user_id)
profile = await load_profile(user_id)
permissions = await check_permissions(user_id)

# 业务走到这里才真正需要模型结果
response = await model_task
```

### `create_task()` 后任务会立刻运行吗？

严格说：`create_task()` 会把协程注册成 Task，并标记为可以运行。

但它不一定在这一行立刻开始执行。因为此刻正在运行的是当前协程。只有当当前协程遇到 `await`、结束，或者以其他方式把控制权交还给事件循环后，事件循环才有机会调度刚刚创建的 Task。

例如：

```python
model_task = asyncio.create_task(model.ainvoke(question))
history = await load_history(user_id)
```

执行到 `await load_history(...)` 时，当前协程暂停，事件循环就可以开始推进 `model_task`。

但如果写成这样：

```python
model_task = asyncio.create_task(model.ainvoke(question))

time.sleep(5)

response = await model_task
```

`time.sleep(5)` 会阻塞整个线程。事件循环拿不到控制权，`model_task` 虽然已经被创建了，但很可能没机会运行。模型请求可能要等到 5 秒后执行到 `await model_task` 时才真正开始推进。

## 6. `gather()`：多个任务一起跑，并等待全部完成

如果有多个地位相近、互不依赖的异步任务，希望它们一起开始，并在全部完成后继续，可以用 `asyncio.gather()`：

```python
response, history, profile = await asyncio.gather(
    model.ainvoke(question),
    load_history(user_id),
    load_profile(user_id),
)
```

这段代码的语义是：

```text
把三个协程都安排成任务
当前协程在这里暂停
事件循环并发推进这三个任务
三个任务全部完成后，当前协程恢复
按传入顺序返回结果
```

`gather()` 会自动把传入的协程包装成任务。它适合表达：

```text
这几件事情互不依赖，我希望它们同时开始，我等它们全部完成。
```

### `gather()` 可以先启动，稍后再 await 吗？

可以。

```python
group = asyncio.gather(
    model.ainvoke(question),
    load_history(user_id),
    load_profile(user_id),
)

# 当前协程继续做别的异步工作
other = await do_other_work()

# 稍后再统一拿这一组任务的结果
response, history, profile = await group
```

这和 `create_task()` 的“先启动、稍后拿结果”很像，只不过：

```text
create_task() 管理的是一个任务
gather() 管理的是一组任务的聚合结果
```

但是不要这样写：

```python
asyncio.gather(a(), b(), c())  # 不保存、不 await，不推荐
```

如果任务里出现异常，不保存也不等待会让问题变得难追踪。

通常推荐：

```python
results = await asyncio.gather(a(), b(), c())
```

或者：

```python
group = asyncio.gather(a(), b(), c())
...
results = await group
```

## 7. 并发的关键

一句话：

```text
并发的关键 = 多个任务已经被调度 + 当前协程在 await 处让出事件循环。
```

只有 `await`，但没有多个已调度任务，不会自动并发。

比如这个不是并发：

```python
response = await model.ainvoke(question)
history = await load_history(user_id)
profile = await load_profile(user_id)
```

它是顺序等待。

这个才有并发机会：

```python
model_task = asyncio.create_task(model.ainvoke(question))

history = await load_history(user_id)
profile = await load_profile(user_id)

response = await model_task
```

因为 `model_task` 已经被安排成独立任务。后面 `await load_history(...)` 时，当前协程让出事件循环，事件循环就可以顺便推进 `model_task`。

这个也有并发机会：

```python
response, history, profile = await asyncio.gather(
    model.ainvoke(question),
    load_history(user_id),
    load_profile(user_id),
)
```

因为 `gather()` 把三个协程都安排成了任务，然后当前协程在这里等待它们全部完成。

## 8. 并发不是并行

在一个线程里的 `asyncio` 中，Python 代码通常不是同时在 CPU 上运行的，而是交替推进：

```text
Task A 跑一会儿，遇到 await，暂停
Task B 跑一会儿，遇到 await，暂停
Task C 跑一会儿，遇到 await，暂停
某个 I/O 完成后，Task A 从上次暂停的位置继续跑
```

所以这里说的是并发，不是 CPU 层面的并行。

并发：

```text
一个线程，多个任务交替推进。
```

并行：

```text
多个 CPU 核心、多个线程或多个进程同时执行。
```

异步 I/O 的价值在于：模型调用、数据库请求、HTTP 请求、向量库请求等大部分时间都在等待外部响应。等待期间 Python 不应该阻塞当前线程，而应该把事件循环让出去，去推进别的任务。

所以可以说：

```text
asyncio 节省的是等待时间，不是让 CPU 同时执行多段 Python 代码。
```

如果任务是大量 CPU 计算，比如：

```python
for i in range(10_000_000_000):
    ...
```

并且中间没有任何 `await`，事件循环就没有机会切走，其他异步任务也会被卡住。这类 CPU 密集任务通常应该考虑多进程、线程池、进程池，或者专门的计算服务。

## 9. `asyncio.sleep()` 和 `time.sleep()` 的区别

异步代码里最经典的坑是把：

```python
await asyncio.sleep(1)
```

写成：

```python
time.sleep(1)
```

二者看起来都是等 1 秒，但含义完全不同。

`asyncio.sleep()`：

```text
当前协程暂停 1 秒，把事件循环让出去。
其他任务可以继续运行。
```

`time.sleep()`：

```text
当前线程真的睡 1 秒。
事件循环也被堵住。
其他异步任务没有机会运行。
```

因此在异步函数里要尽量避免同步阻塞操作：

```python
time.sleep(...)
requests.get(...)
subprocess.run(...)
普通同步数据库请求
大量 CPU 计算
```

对应优先使用异步版本：

```python
await asyncio.sleep(...)
await async_http_client.get(...)
await async_db.fetch(...)
await model.ainvoke(...)
```

## 10. 三种写法的选择

### 直接 `await`

```python
response = await model.ainvoke(question)
```

适合：

- 当前流程里只有一个异步任务。
- 后面的逻辑依赖这个结果。
- 你追求最简单清楚的代码。

如果只是一个普通脚本，而且没有并发需求，同步版本也可以：

```python
response = model.invoke(question)
```

单次调用不会因为 `ainvoke()` 就神奇变快。异步 API 的价值主要体现在整个程序需要同时处理多个 I/O 等待时。

### `create_task()` + 稍后 `await`

```python
model_task = asyncio.create_task(model.ainvoke(question))

history = await load_history(user_id)
profile = await load_profile(user_id)

response = await model_task
```

适合：

- 想先启动一个耗时 I/O 任务。
- 当前流程后面还有其他异步准备工作。
- 稍后某个位置才真正需要这个任务的结果。

### `gather()`

```python
response, history, profile = await asyncio.gather(
    model.ainvoke(question),
    load_history(user_id),
    load_profile(user_id),
)
```

适合：

- 多个任务互不依赖。
- 多个任务地位相近。
- 希望一起启动，并统一等待全部完成。

## 11. 与 LangChain 异步 API 的关系

LangChain 里：

```python
model.invoke(...)
```

是同步调用，会阻塞当前线程直到模型完整返回。

```python
await model.ainvoke(...)
```

是异步调用。它等待模型响应时可以把事件循环让出去，让其他异步任务继续运行。

如果你在普通 `.py` 脚本中只调用一次模型：

```python
response = model.invoke("你好")
```

通常更简单。

如果你已经在异步环境里，比如 FastAPI、WebSocket、LangGraph async node、异步任务队列，或者你要并发多个 I/O 任务，就应该使用：

```python
response = await model.ainvoke("你好")
```

并发多个模型调用或 I/O 调用时：

```python
responses = await asyncio.gather(
    model.ainvoke("问题 1"),
    model.ainvoke("问题 2"),
    model.ainvoke("问题 3"),
)
```

或者使用 LangChain 自己提供的批量异步接口：

```python
responses = await model.abatch(
    ["问题 1", "问题 2", "问题 3"],
    config={"max_concurrency": 3},
)
```

## 12. 最终速记

```python
await coro()
```

现在等待这个协程完成。当前协程暂停，完成后继续。不会自动创建独立后台任务。

```python
task = asyncio.create_task(coro())
```

把协程注册成独立后台 Task。当前协程继续往下走。

```python
result = await task
```

需要结果了，再等待这个后台任务。任务如果已经完成，直接拿结果。

```python
results = await asyncio.gather(coro1(), coro2(), coro3())
```

把一组协程安排成任务，并在这里等待全部完成。

```python
group = asyncio.gather(coro1(), coro2(), coro3())
...
results = await group
```

先安排一组任务运行，当前协程继续做别的事，稍后再统一拿结果。

最后记住这一句：

```text
asyncio 的并发不是多个 Python 代码同时跑，
而是多个任务在 I/O 等待点主动让路、交替推进。
它节省的是等待时间，不是让 CPU 同时执行多段 Python 代码。
```
